# `chips/`

The chip models behind the bus-model machines (`--machine wendy2c` and
`--machine michael`). Each module fills in a `struct chip` (`bus.h`): a
`tick`, `read`, `write` and `reset` method, any of which may be NULL.
`bus_step()` calls every chip's `tick` once per oscillator tick;
`bus_read`/`bus_write` offer an access to the chips in registration order
and the first one that claims it wins. Each header describes the pin
wiring and behaviour in detail; this table says what is here and who
uses it.

| Module | Models | Used by |
|---|---|---|
| `clock_22v10` | the 22V10 PLD: CPU clock (CKS/CK), `/ROMCS`, `/RAMCS`, `/VIACS`, RAM bank bits R15..R18, from `clock_22v10_pld_generated.h` | wendy2c |
| `clock_22v10_pld_generated.h` | generated by `../pld_to_c.py` from `hardware/wendy2/22V10-wendy2c.pld` (the Makefile regenerates it); do not edit | wendy2c |
| `rom_28c256` | 32 KiB ROM loaded from a file; writes ignored | wendy2c, michael |
| `ram_628128` | the wendy2c's 512 KiB banked SRAM (the name is historical); also the plain RAM in michael | wendy2c, michael |
| `via_6522` | the 6522 VIA: registers, T1/T2, shift register, CB2 edge, IFR/IER, port pins, and the bank-config feedback to the PLD | wendy2c, michael |
| `cpu_65c02` | the CPU on the bus: runs one instruction per CPU clock and owes the remaining cycles (`../cpu_core.c` does the work) | wendy2c, michael |
| `lcd_hd44780` | HD44780 LCD (4-bit or 8-bit, 16x2 up to 20x4, 5x8 and 5x10 cells, DDRAM/CGRAM) on VIA pins set per machine; `hd44780_a00_font.h` is the character ROM | wendy2c, michael |
| `serial_usb` | the USB serial chip: feeds queued bytes (`--serial-input`) into the VIA's CB2/SR | wendy2c, michael |
| `led_buttons` | LED taps (PB6, PA2) and the control button injected on PA1 | wendy2c |
| `syscall_ports` | host file I/O at `$F800-$F80F`, registered only with `--disk DIR` (see `prog8/WENDY2_DISK_BOOT_DESIGN.md`) | wendy2c |
| `glue_michael` | Michael's address decode and the `--ram` decoding variants | michael |
| `ps2_keyboard_board` | Michael's PS/2 keyboard board at frame level (`--keys`, `--kbd-scancodes`, `--kbd-fault`) | michael |
| `osc` | the crystal frequency only; no machine registers it (it is only exercised by `tests/test_chip_osc.c`) | tests |

Most modules have a matching `tests/test_chip_*.c` or `tests/test_*.c`
(see `../tests/README.md`); `glue_michael`, `ps2_keyboard_board` and
`syscall_ports` have no unit test of their own and are exercised by the end-to-end tests.
